## 面试追问与答题方向

1. 为什么选 least-inflight 而不是 round-robin？不同请求长度下静态轮转不感知运行中的请求数；least-inflight 用当前活动数作近似，但不能反映 Token 预算或显存负载。
2. 为什么限制单后端并发？避免过多并发导致 OOM/排队爆炸；而实际 vLLM 会调度批处理，固定并发并不总是吞吐最优。
3. 429/503 和超时分别怎么处理？429/5xx/网络故障计入熔断；避免透明重试导致重复推理成本。
4. SSE 流式为什么要 Flush？避免网关把增量数据缓存在自身；上游 chunk 不等于 token，一个事件也不一定恰好包含一 token。
5. P95 的含义？本项目是有限窗口成功/失败 HTTP 请求完成时间的经验分位数，混合负载时不等于模型 ITL 或 TTFT。
6. 如何改为生产系统？模型路由按队列/显存/KV 利用率，Prometheus/Grafana 可观测性，分布式配置协调，TLS+多租户认证，追踪和成本优化。
7. 如果多实例网关如何防止超额请求？当前每实例 cap 不能保证全局 cap，应引入共享资源配额/集中准入方案。
8. 你的 Go 项目和 CUDA/Triton 什么关系？Go 负责控制面/服务层，CUDA/Triton 负责 GPU 计算层；不能把网关优化说成 Kernel 加速。
